## รายละเอียดฟีเจอร์

### 20260802-001 — ระบบสั่งกาแฟจากโต๊ะด้วยการสแกน QR Code (`Must have`)

ลูกค้าสแกน QR code ประจำโต๊ะเพื่อสั่งเมนู ออเดอร์เข้าคิวบาริสต้าโดยตรง เมื่อทำเสร็จระบบแจ้งเตือนพนักงานเสิร์ฟอัตโนมัติ พร้อมแสดงสถานะออเดอร์แบบ real-time ให้ลูกค้าเห็น และผู้จัดการร้าน/บาริสต้าปิด-เปิดเมนูชั่วคราวได้

**เหตุผลจัดลำดับ:** เป็น core business flow ของทั้งระบบ — ร้านใช้งานระบบไม่ได้เลยถ้าไม่มีฟีเจอร์นี้ (จัดตามเกณฑ์ default: flow หลักที่ระบบใช้งานไม่ได้เลยถ้าขาด)

**เอกสารต้นทาง:** [[01-spec/20260802-001-table-qr-ordering.md|20260802-001-table-qr-ordering.md]]

### 20260802-002 — หน้า Dashboard ดูยอดขาย (`Should have`)

เจ้าของร้าน/แอดมินดูยอดขายรวมและจำนวนออเดอร์ตามช่วงเวลา preset ("วันนี้", "สัปดาห์นี้", "เดือนนี้")

**เหตุผลจัดลำดับ:** spec ระบุไว้เองในหมายเหตุว่าเป็น "Medium priority ... มีประโยชน์แต่ไม่ใช่ core flow ที่บล็อกการใช้งานร้าน" จึงจัดเป็น Should have — สำคัญรองจาก flow การสั่งกาแฟหลัก แต่ร้านยังเปิดขายได้ถ้ายังไม่มีฟีเจอร์นี้

**เอกสารต้นทาง:** [[01-spec/20260802-002-sales-dashboard.md|20260802-002-sales-dashboard.md]]

### 20260802-003 — ระบบบันทึก Log (Audit Trail) (`Should have`)

บันทึก log เหตุการณ์สำคัญ (สร้าง/เปลี่ยนสถานะออเดอร์, เปิด-ปิดเมนู, การเข้าถึง dashboard) พร้อม timestamp และผู้ทำรายการ เก็บไว้ 90 วันแล้วลบอัตโนมัติ จำกัดสิทธิ์ดูเฉพาะผู้จัดการร้าน/แอดมิน

**เหตุผลจัดลำดับ:** spec ระบุไว้เองในหมายเหตุว่าเป็น "Medium priority ... supporting feature เพื่อความโปร่งใส/ตรวจสอบได้ ไม่ใช่ core flow" จึงจัดเป็น Should have

**เอกสารต้นทาง:** [[01-spec/20260802-003-audit-log.md|20260802-003-audit-log.md]]

### 20260802-004 — ขอความยินยอม (Consent) ตาม PDPA จากพนักงาน (`Could have`)

พนักงานทุกคนต้องกดยินยอมครั้งเดียวตอน onboarding ก่อนใช้งานระบบได้ ระบบบันทึกสถานะยินยอมพร้อม timestamp แบบถาวร

**เหตุผลจัดลำดับ:** แม้ spec จะระบุว่าเป็นเงื่อนไข mandatory gate ที่บล็อกการใช้งานระบบทั้งหมดหากไม่ยินยอม (ซึ่งเข้าเกณฑ์ Must have ได้เช่นกัน) แต่ผู้ใช้ยืนยันให้จัดเป็น **Could have** เนื่องจากธุรกิจขนาดเล็กแบบร้านกาแฟนี้ยังไม่มีการบังคับใช้ PDPA อย่างเข้มงวด จึงมองว่าเป็นส่วนเสริมที่ทำทีหลังได้โดยไม่กระทบการเปิดร้าน (เป็นการตัดสินใจของ user ไม่ใช่การใช้เกณฑ์ default)

**เอกสารต้นทาง:** [[01-spec/20260802-004-pdpa-consent.md|20260802-004-pdpa-consent.md]]
