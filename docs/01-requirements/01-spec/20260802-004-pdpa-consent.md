# ขอความยินยอม (Consent) ตาม PDPA จากพนักงาน

**วันที่:** 2026-08-02
**สถานะ:** ร่าง (Draft)

## ที่มา / บริบท

ระบบเก็บข้อมูลบัญชีพนักงาน (พนักงานเสิร์ฟ, บาริสต้า, ผู้จัดการร้าน) และมีการบันทึก log การทำงานของพนักงานตาม [[20260802-003-audit-log|ระบบบันทึก Log (Audit Trail)]] ซึ่งเข้าข่ายเป็นข้อมูลส่วนบุคคลภายใต้พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล (PDPA) เจ้าของโปรเจกต์ยืนยันชัดเจนว่าต้องการทำ PDPA ให้ "ง่ายและทำเท่าที่จำเป็นเท่านั้น" ไม่ต้องมีกระบวนการซับซ้อน เช่น DPO, data breach notification process แบบละเอียด หรือสิทธิเจ้าของข้อมูลแบบครบทุกมิติ — ขอบเขตของ requirement นี้เจาะจงเฉพาะเรื่อง consent อย่างง่ายเท่านั้น

ปัจจุบันระบบไม่มีการเก็บข้อมูลส่วนบุคคลของลูกค้า (ลูกค้าสั่งผ่าน QR โดยไม่ login ไม่มีบัญชี) ดังนั้น requirement นี้ครอบคลุมเฉพาะ consent จากพนักงานเท่านั้น

## ความต้องการ (Requirement)

พนักงานทุกคน (พนักงานเสิร์ฟ, บาริสต้า, ผู้จัดการร้าน) ที่มีบัญชีผู้ใช้ในระบบต้องผ่านขั้นตอนขอความยินยอม (consent) ครั้งเดียวตอน onboarding (ตอนสร้างบัญชีผู้ใช้ครั้งแรกในระบบ) ก่อนเริ่มใช้งานระบบ

เนื้อหา consent เป็นแบบง่าย ระบุสั้น ๆ ว่าระบบเก็บข้อมูลอะไรบ้าง (ชื่อ, ข้อมูลบัญชีผู้ใช้, บทบาท) และมีการบันทึก log การทำงาน (อ้างอิงจาก [[20260802-003-audit-log|ระบบบันทึก Log (Audit Trail)]]) เพื่อวัตถุประสงค์ใด (การบริหารจัดการร้านและตรวจสอบย้อนหลัง)

พนักงานต้องกดยืนยัน/ติ๊กยอมรับ (checkbox หรือปุ่มยืนยัน) ก่อนจึงจะใช้งานระบบต่อได้ ระบบบันทึกว่ายินยอมแล้วพร้อม timestamp หากพนักงานไม่กดยินยอม จะไม่สามารถใช้งานระบบได้ เพราะเป็นเงื่อนไขจำเป็นขั้นต่ำในการทำงาน

## ขอบเขต (Scope)

### สิ่งที่ต้องทำ (In scope)
- หน้า/ขั้นตอนขอความยินยอม (consent) จากพนักงานครั้งเดียวตอน onboarding ก่อนเริ่มใช้งานระบบ
- แสดงเนื้อหา consent แบบง่าย ระบุข้อมูลที่เก็บ (ชื่อ, ข้อมูลบัญชีผู้ใช้, บทบาท, log การทำงาน) และวัตถุประสงค์ (การบริหารจัดการร้านและตรวจสอบย้อนหลัง)
- ให้พนักงานกดยืนยัน/ติ๊กยอมรับ (checkbox หรือปุ่มยืนยัน) ก่อนใช้งานระบบต่อได้
- บันทึกสถานะการยินยอมพร้อม timestamp ต่อพนักงานแต่ละคนแบบถาวร
- บล็อกการใช้งานระบบหากพนักงานยังไม่กดยินยอม

### สิ่งที่ไม่ทำ (Out of scope)
- สิทธิเจ้าของข้อมูลแบบละเอียด (เช่น ระบบขอดู/แก้ไข/ลบข้อมูลด้วยตนเองผ่าน UI, data portability)
- กระบวนการแจ้งเหตุข้อมูลรั่วไหล (data breach notification) แบบเป็นทางการ
- การแต่งตั้ง DPO (Data Protection Officer) หรือเอกสารนโยบายความเป็นส่วนตัวฉบับเต็มแบบละเอียด
- consent จากลูกค้า เนื่องจากปัจจุบันระบบไม่เก็บข้อมูลส่วนบุคคลของลูกค้า (ถ้าในอนาคตมีฟีเจอร์สมาชิก/ชำระเงินออนไลน์ที่เก็บข้อมูลลูกค้า ต้องพิจารณา requirement เพิ่มเติมแยกต่างหาก)
- การขอ consent ซ้ำเป็นระยะ (ทำครั้งเดียวตอน onboarding พอ ไม่ต้องขอซ้ำทุกครั้งที่ login)

## กฎทางธุรกิจ / เงื่อนไข (Business Rules)
- พนักงานทุกคนต้องยินยอมก่อนจึงจะใช้งานระบบได้ครั้งแรก เป็นเงื่อนไขบังคับ (mandatory gate) ไม่ใช่ optional
- บันทึกสถานะการยินยอมพร้อม timestamp ต่อพนักงานแต่ละคน เก็บเป็นข้อมูลถาวร ไม่ใช่ log ที่ถูกลบตาม retention 90 วันของ audit log
- ขอ consent เพียงครั้งเดียวตอน onboarding ไม่ต้องขอซ้ำทุกครั้งที่ login
- ผู้ใช้/บทบาทที่เกี่ยวข้อง: พนักงานเสิร์ฟ, บาริสต้า, ผู้จัดการร้าน (ทุกคนที่มีบัญชีผู้ใช้ในระบบต้องผ่านขั้นตอนนี้)
