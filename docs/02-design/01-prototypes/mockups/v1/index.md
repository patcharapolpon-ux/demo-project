**วันที่สร้าง/อัปเดตล่าสุด:** 2026-08-16

## Interactivity ที่เพิ่มเข้ามา (2026-08-16)

4 หน้าจอเชื่อมโยงกันจริงด้วย vanilla JS (ไม่มี framework/CDN) ผ่าน localStorage keys ต่อไปนี้:

- `coffeeOrderCart` — array ของรายการในตะกร้า (ใช้ร่วมกันระหว่างหน้าเมนู, หน้าปรับตัวเลือก, หน้าตะกร้า)
- `coffeeOrderStatus` — สถานะออเดอร์ปัจจุบัน (`รับออเดอร์แล้ว` / `กำลังทำ` / `เสร็จแล้ว` / `เสิร์ฟแล้ว`)
- `coffeeLastOrder` — snapshot ของออเดอร์ล่าสุดที่ยืนยันแล้ว (รายการ+ยอดรวม) บันทึกตอนกด "ยืนยันสั่ง" เพื่อให้หน้าสถานะออเดอร์แสดงรายการที่สั่งจริงได้

### วิธีทดสอบ

**สำคัญ:** ต้องเปิดผ่าน local web server ไม่ใช่เปิดไฟล์ตรง ๆ ผ่าน `file://` เพราะบางเบราว์เซอร์ (โดยเฉพาะ Chrome) จำกัดสิทธิ์ `localStorage` บน origin แบบ `file://` ทำให้ state ไม่ถูกบันทึก/อ่านข้ามหน้าได้ วิธีเปิดทดสอบง่าย ๆ:

1. เปิด terminal ที่โฟลเดอร์นี้ (`docs/02-design/01-prototypes/mockups/v1/`)
2. รันคำสั่ง `python -m http.server 8000` (หรือใช้ VS Code extension "Live Server" ถ้ามี)
3. เปิดเบราว์เซอร์ไปที่ `http://localhost:8000/001-menu.html`
4. ทดสอบ flow: กดเมนู -> ปรับตัวเลือก -> เพิ่มลงตะกร้า -> เปิดตะกร้า (ไอคอนมุมบน) -> ยืนยันสั่ง -> ดูสถานะออเดอร์ -> กด "จำลองขั้นถัดไป" ไล่สถานะจนถึง "เสิร์ฟแล้ว"

หากต้องการเริ่มทดสอบใหม่ตั้งแต่ต้น ให้เปิด Developer Tools > Application/Storage > Local Storage แล้วลบ key `coffeeOrderCart`, `coffeeOrderStatus`, `coffeeLastOrder` (หรือรันคำสั่ง `localStorage.clear()` ใน console)

## ดุลยพินิจเพิ่มเติมที่ใช้ระหว่างออกแบบ

- **สีเส้นขอบ input/เส้นแบ่งเบา ๆ:** DESIGN.md ระบุเพียง "สีเทาอ่อน" โดยไม่ได้ให้ hex ที่แน่นอนสำหรับ border ของ form input และเส้นแบ่งเนื้อหา จึงเลือกใช้ `#E0E0E0` และ `#F0F0F0` เป็นค่าประมาณที่ใกล้เคียงโทนเทาอ่อนของระบบ
- **Font family:** DESIGN.md แนะนำแต่ไม่ได้ fix ชื่อฟอนต์ตายตัว จึงเลือกใช้ `'Noto Sans Thai', 'IBM Plex Sans Thai', sans-serif` ตามที่ระบุเป็นตัวอย่างแนะนำในเอกสาร
- **ปุ่ม "สั่งเพิ่มเมนู" ในหน้าสถานะออเดอร์:** เป็น secondary action ที่เพิ่มเข้ามาเพื่อรองรับการใช้งานจริง (ลูกค้าสั่งเพิ่มระหว่างรอ) — ไม่ขัดกับ UX rule เพราะหน้านี้ไม่มีปุ่ม primary อยู่แล้ว (real-time status เป็น primary view ตามที่ spec/DESIGN.md กำหนด)
- **หมวดหมู่เมนูและตัวเลือกท็อปปิ้ง/ราคา:** เป็นตัวอย่างข้อมูลสมมติเพื่อสาธิต UI เท่านั้น ไม่ใช่ข้อมูลจริงจาก spec (spec ระบุแค่ประเภทตัวเลือกที่ต้องมี ไม่ได้ระบุรายการ/ราคาจริง)

- 2026-08-16: เพิ่มไฟล์ `001-standalone.html` — รวม 4 หน้าจอ interactive prototype ข้างต้นเข้าเป็นไฟล์เดียว โดยแปลง cross-file navigation + localStorage ให้เป็น in-page section switching (`showScreen(slug)`) + state ในหน่วยความจำ JS ล้วน เพื่อให้เปิดทดสอบตรงผ่าน `file://` ได้ทันทีโดยไม่ต้องตั้ง local web server; ระหว่างแปลงพบและแก้บั๊ก checkbox "เพิ่มช็อตเอสเพรสโซ" ที่เคย default checked ผิดพลาดในหน้าปรับตัวเลือกเมนู ทำให้ไฟล์ standalone นี้เริ่มต้นราคารวมตรงกับราคาฐานของเมนูที่เลือกจริง; ไม่ได้แก้ไข 4 ไฟล์แยกเดิม (ยังคงมีบั๊กเดิมอยู่เพราะ caller ระบุให้แก้เฉพาะในไฟล์ standalone)
