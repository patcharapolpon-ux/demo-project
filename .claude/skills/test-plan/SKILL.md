# Test Plan — สร้าง/อัปเดตแผนการทดสอบภาพรวมของโปรเจกต์

Skill นี้ทำงานใน main conversation ทั้งหมด (รวบรวม NFR, ถามเมื่อคลุมเครือ) แล้วค่อยส่งงานเขียนไฟล์ให้ subagent `test-plan-writer` ทำในขั้นตอนสุดท้ายเท่านั้น ไฟล์นี้เป็น **living document เดียวต่อโปรเจกต์** ไม่มีการระบุขอบเขตเฉพาะบางรายการเหมือน acceptance-criteria/test-case

## ขั้นตอน

### 1. สำรวจข้อมูลต้นทาง

- Read `docs/01-requirements/backlog.md` และ `docs/01-requirements/feature-list.md` (ถ้ามี)
- Glob `docs/01-requirements/01-spec/*.md` (ยกเว้น `index.md`)
- Glob `docs/03-testing/01-test-plan/test-plan.md` เพื่อดูว่ามีไฟล์เดิมอยู่แล้วหรือไม่ (Read ถ้ามี เพื่อดูว่าเคยมี NFR/environment ระบุไว้แล้วหรือยัง)

### 2. รวบรวม Non-Functional Requirement (NFR) — ถามเสมอเมื่อยังไม่มีข้อมูล

โปรเจกต์นี้ยังไม่มีเอกสาร spec ที่ระบุ NFR ไว้ชัดเจน ดังนั้น:

- ถ้าไฟล์ test-plan.md เดิมมีหัวข้อ NFR ที่กรอกไว้ครบแล้ว และ backlog/feature-list ไม่มี feature ใหม่ที่กระทบ NFR → ใช้ข้อมูลเดิมต่อได้เลย ไม่ต้องถามซ้ำ
- ถ้ายังไม่มีข้อมูล NFR เลย หรือมี feature ใหม่ที่อาจกระทบ NFR (เช่น real-time status, ข้อมูลลูกค้า/PDPA) ให้ AskUserQuestion ถาม user เพื่อรวบรวม NFR อย่างน้อยในมิติต่อไปนี้ (แยกถามทีละมิติหรือรวมเป็นชุดคำถามเดียวก็ได้ตามความเหมาะสม) พร้อมตัวเลือกแนวทางอย่างน้อย 3 แบบต่อคำถาม เช่น:
  - **Performance**: 1) ไม่ระบุเกณฑ์ตอนนี้ (ปล่อยว่างไว้ก่อน) 2) ระบุเวลาตอบสนองคร่าว ๆ เอง (เช่น "หน้าสั่งอาหารต้องโหลดไม่เกิน 3 วินาที") 3) ให้ Claude เสนอเกณฑ์ทั่วไปของระบบร้านกาแฟขนาดเล็กมาให้เลือก
  - **Security**: 1) ไม่ระบุตอนนี้ 2) ระบุเอง (เช่น ข้อมูลลูกค้าต้องไม่เก็บถาวรเกินความจำเป็น ตาม PDPA) 3) ให้ Claude เสนอเกณฑ์มาตรฐานทั่วไป
  - **Usability/Availability**: ทำนองเดียวกัน
- ถ้า user เลือก "ไม่ระบุตอนนี้" ในมิติใด ให้บันทึกไว้ว่ามิตินั้นยังไม่มีข้อมูล (ห้าม subagent เดาเกณฑ์เอง)

### 3. ตรวจสอบประเด็นคลุมเครืออื่น (ถ้ามี)

ถ้า test environment จริง (อุปกรณ์, เบราว์เซอร์, เครือข่าย) ยังไม่ชัดเจนและกระทบการวางแผนทดสอบอย่างมีนัยสำคัญ ให้ AskUserQuestion ถามพร้อมตัวเลือกอย่างน้อย 3 แบบ มิฉะนั้นข้ามไปขั้นตอน 4 ได้เลย

### 4. ส่งงานให้ subagent `test-plan-writer`

เรียก Agent tool ด้วย `subagent_type: "test-plan-writer"` (foreground เพื่อรอผลก่อนตอบ user) พร้อมส่ง:

- วันที่ปัจจุบัน (YYYY-MM-DD)
- ข้อมูล NFR ทั้งหมดที่รวบรวมได้จากขั้นตอน 2 (หรือระบุชัดเจนว่ามิติไหนยังไม่มีข้อมูล)
- การตัดสินใจเรื่อง environment/ประเด็นอื่นจากขั้นตอน 3 (ถ้ามี)

### 5. รายงานผลกลับ user

สรุป path ไฟล์ test-plan.md, หัวข้อที่เขียน/แก้ไข, และแจ้งว่าหัวข้อไหนยังขาดข้อมูล NFR (ถ้ามี) พร้อมชวน user เพิ่มข้อมูลได้ภายหลังด้วยการรัน `/test-plan` ซ้ำ

## หมายเหตุ

- ไฟล์ `docs/03-testing/01-test-plan/test-plan.md` เป็น living document เดียวของทั้งโปรเจกต์ — อัปเดตทับเนื้อหาหลักเสมอ แต่คงหัวข้อ "ประวัติการแก้ไข" ท้ายไฟล์ไว้ (ต่อท้าย ไม่ลบของเดิม)
- ต่างจาก `acceptance-criteria` และ `test-case` ตรงที่ skill นี้ไม่มีขั้นตอน "กำหนดขอบเขตเฉพาะบางรายการ" เพราะ test plan ต้องมองภาพรวมทั้งโปรเจกต์เสมอ
